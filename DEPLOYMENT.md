# GitHub Pages Deployment Guide (`DEP1`)

This guide explains how to upload `DEP1` to your GitHub repository and enable automated builds and deployments via **GitHub Actions** and **GitHub Pages**.

---

## 1. Architecture & Hosting Compatibility

- **Hosting Model:** Static SPA (`dist/` generated by Vite `6.0.3` + `tsc -b`).
- **Client-Side Routing on GitHub Pages:** `vite.config.ts` automatically generates `dist/404.html` matching your repository's `base` path, and `index.html` restores the exact requested route before React Router (`<BrowserRouter basename={import.meta.env.BASE_URL}>`) mounts. Refreshing `/solutions/zkteco-attendance`, `/about`, or `/contact` works without 404 errors.
- **Dynamic Assets:** Event images (`import.meta.env.BASE_URL`), favicons (`./favicon.svg`), and lazy JS chunks resolve cleanly under both project subpaths (`https://<user>.github.io/<repo>/`) and custom domains (`https://www.rubik-is.com/`).
- **Contact Form (`POST /api/contact`):** Because GitHub Pages serves static files only, `POST /api/contact` is only active in local `vite` dev/preview mode. For live form submissions on GitHub Pages, set the public `VITE_CONTACT_ENDPOINT` repository variable to an external form endpoint (e.g., Formspree or your own API), or rely on the built-in `mailto:info@rubik-is.com` fallback.

## 2. Uploading `DEP1` to a New GitHub Repository

1. Create a new repository on GitHub (do **not** initialize with a README if pushing from `DEP1`).
2. Inside the `DEP1/` directory (never from the parent workspace), initialize Git and push:

```bash
cd DEP1
git init
git branch -M main
git add .
git commit -m "chore: initial production release (DEP1)"
git remote add origin https://github.com/<your-username>/<your-repo>.git
git push -u origin main
```

## 3. One-Time GitHub Repository Setup

1. Open your repository on GitHub → **Settings** → **Pages**.
2. Under **Build and deployment → Source**, select **GitHub Actions** (do *not* select "Deploy from a branch").
3. *(Optional)* Under **Settings → Secrets and variables → Actions → Variables**, add any public build-time variables:
   - `VITE_GA_MEASUREMENT_ID` (e.g., `G-XXXXXXXXXX`)
   - `VITE_GTM_ID` (e.g., `GTM-XXXXXXX`)
   - `VITE_CONTACT_ENDPOINT` (optional external form API URL)
   - `VITE_BASE_PATH` (only needed if overriding the auto-detected GitHub Pages base path; e.g., `/` for a custom domain)

> [!IMPORTANT]
> Never store private API secrets or SMTP credentials in `VITE_*` variables — Vite embeds `VITE_*` values directly into client-side JavaScript.

---

## 4. How Automatic Deployment Works

- **Pull Requests & Pushes (`.github/workflows/ci.yml`):** Runs `npm ci`, TypeScript checks, Vitest unit & integration tests, security audit, production build, and Playwright browser tests (E2E, WCAG 2.2 AA, SEO, Analytics).
- **Production Deployment (`.github/workflows/deploy.yml`):** Triggers on every push to `main` (or manually via **Actions → Deploy – GitHub Pages Production → Run workflow**). It runs all quality gates first; only if every gate passes does it upload `dist/` via `actions/upload-pages-artifact@v3` and publish via `actions/deploy-pages@v4`.

---

## 5. Custom Domain Setup (Future)

1. In GitHub **Settings → Pages → Custom domain**, enter your domain (e.g., `www.rubik-is.com`) and enable **Enforce HTTPS**.
2. Add a `CNAME` file inside `DEP1/public/CNAME` containing `www.rubik-is.com` (Vite copies it to `dist/CNAME`), or set repository variable `VITE_BASE_PATH=/`.
3. `actions/configure-pages@v5` will automatically detect the custom domain and build with `base: /`.

---

## 6. Updating Production & Troubleshooting

- **Publishing Updates:** Copy/sync approved changes from your development workspace into `DEP1/`, run `npm run test:all` locally inside `DEP1/`, and push to `main`.
- **Deployment Fails on Quality Gate:** Open the failed job in GitHub **Actions**, inspect the step logs (or download the `playwright-failure-report` artifact), fix the issue in `DEP1/`, and push again.
- **404 on Direct Subpath Refresh:** Confirm `Source: GitHub Actions` is selected in **Settings → Pages** and that `dist/404.html` was generated during `npm run build`.
